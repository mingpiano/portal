# 设计决定和理由

**为什么用 Apps Script + Sheets + GitHub Pages**：全免费、老师自己的账号、数据在老师能直接打开的表格里。代价是 Apps Script 有额度和并发限制，所以后台写操作都加锁、读操作尽量一次取齐。

**权限在服务器，不在网页**：`buildState_` 只返回当前登录者能看的数据。学生拿不到别人的名字，家长只看到配对的孩子，成人学生的留言只有本人和老师能看。每次请求都重新核对账号是否还有效（归档、改邮箱后旧登录立刻作废）。测试里有“权限矩阵”：每个后台操作 × 每种身份都要登记，新增操作没登记测试就会失败。

**登录**：6 位验证码（存的是加盐哈希，10 分钟有效、最多试 5 次、只能用一次）；每个邮箱每小时 3 封、每天 8 封；全站每天 60 封。不认识的邮箱也返回同样的结果，不暴露谁有账号。登录令牌在浏览器里是 64 位随机串，服务器只存它的哈希；“记住我”90 天，否则 1 天。

**表格里全部存成纯文本**：避免 Sheets 把 `2018-03-04` 变日期、`007` 变 7、`=开头的文字` 变公式。读的时候按列类型转换。列按表头名字匹配，老师在表格里调换列顺序或加备注列都不影响。

**积分不存分数，只存事实**：存“几点签的字”，每次按当前规则现算。老师改规则，所有人的积分立刻按新规则重算。

**学费**：`paid`（已交几期）× 10 − （`carry` 上线前已上 + 系统里记的课）= 剩余。≤ 0 就该交。

**测试 / 正式环境**：Script Properties 里的 `ENV`。测试环境邮件只发给“老师邮箱 + 别名”；`resetTestData` 在正式环境拒绝运行。

**本机模拟**：`tools/dev/gas-mock.js` 在 Node 里原样运行 `apps-script/*.js`，并刻意复制 Sheets 的自动改写坑，所以测试能抓到“忘了设纯文本”这类错误。

**网页安全**：没有构建步骤、没有内联脚本；`index.html` 带内容安全策略（只允许本站脚本，只允许连 Apps Script）；所有用户内容进模板前转义，测试里用恶意名字、曲目、留言验证不会执行。

**未决问题**：老师写的内容（曲目、重点、作业、通知）是否自动翻译。第一期原样显示老师写的文字，不翻译；以后要做，接入点在显示层。
